# Contour D — zoom→page reveal fix (Zulip 630601038)

Scope: `assets/contour/board/hero.css` only. HAND_P0=0.30, S0=0.42, hero.js, board chrome/copy untouched.

## Symptom

During scroll-zoom into the D hole, `#main` did not show through the hole mid-flight. The page only appeared at the end of the animation (hard cut), instead of the board-locked overlap + sticky pin + circle clip reveal (HANDOFF-630402395).

## Cause

Overnight CLS commit `55df185` inserted the pre-paint `__dpHeroLayout` `<script>` between `#hero` and `#main` in `variants/d.html`. Handoff CSS used the **adjacent** sibling combinator:

```css
.js #hero.board-hero + #main { … }
.js #hero.board-hero + #main.handoff { position: sticky; … }
```

With a script node in between, those rules no longer matched. Computed `position` on `#main.handoff` fell back to `static`, so the sticky pin never engaged and `#main` stayed below the viewport until the sticky stage released.

Verified (headless Chrome, tip `b06c117` vs `798266f`): at p≈0.50, bad tip had `pos=static` / `rect.top≈4189`; good tip had `pos=sticky` / `rect.top≈179`.

## Fix

Switch `+` → `~` (general sibling) so the relative z-index and sticky pin still apply when a script (or any non-`#main` node) sits between `#hero` and `#main`. Comment in hero.css documents why.
